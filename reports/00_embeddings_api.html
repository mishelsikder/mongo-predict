  • Across 26 (task, mode) pairs the wrapper stages (fetch + JSON + tabular) got 2.4x faster (median; 1.3x to 5.9x) and the end to end fit 3.4x faster; peak memory changed by a median factor of 1.02x.
  • The code changes behind these numbers (orjson serialisation with a per field budget, tabular columns encoded once per call, vectorised column coercion, word n-gram hashing) are listed under "What changed" below.
Setup
  • MongoDB 7.0 standalone on the same machine, sample datasets loaded with python -m demos.load_sample_data.
  • Every (task, mode) pair runs in a fresh process, hashing embedder (256 features, no cache), linear estimator; "before" is commit 55b3540 of the package before it moved to this repository, "after" is the current code. Task definitions are in src/tasks.py.

What changed
  • JSON serialisation uses orjson with a default hook for BSON types instead of a recursive pure-Python conversion followed by json.dumps, and the max_json_chars budget is applied field by field so a huge trailing array (reviews, transactions) is never serialised only to be cut off: 3x to 11x faster per document.
  • Tabular columns are encoded once per call: transform_batches collects the small column frames of all batches and runs the sklearn preprocessing a single time (embeddings still go batch by batch). Per batch sklearn overhead used to dominate on collections of small documents (routes: 2.2 s to 0.7 s for 67k documents).
  • Column coercion is vectorised and dotted paths are pre-split once per column.
  • Hashing embedder defaults to hashed word uni/bigrams instead of character 3-5 grams (about 10x faster on long JSON).
  • Prefetching: in streaming mode the next _id batch is fetched in a background thread while the current one is embedded. Measured separately with voyage-4-nano on 2,048 Airbnb documents: 17.6 / 15.2 s without vs 15.1 / 15.3 s with prefetch, i.e. no measurable gain with a local MongoDB, where fetching is under 1% of the embedding time.
  • Embedding models: bfloat16 on CUDA (float16 overflows in voyage-4-nano and produced NaN vectors; a non-finite batch now triggers a float32 fallback), the token limit is capped at each model's own maximum, texts are grouped by length so a batch holds at most max_batch_tokens, and Matryoshka truncation ("voyage-4-nano@512") is applied after the cache.
  • Fixed: removing a nested target such as scores.0.score from the embedded JSON now descends through arrays; stratified splits pool singleton classes instead of failing.
Computational cost
  • 54 (task, mode) runs (before and after), CPU only, 10 minutes of measured stage time on a shared 176 core box; no GPU (0 H100 node hours).
  • Throughput after the changes: 5,166 training documents per second of end to end fit with the hashing embedder, summed over all runs.
